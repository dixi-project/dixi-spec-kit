# Reading list

## Purpose

Suggest well-known books and resources that explain the ideas this project relies on (spec-driven work, test-driven development, domain-driven design, architecture and operations), so that the team shares background and vocabulary.

## How to use this list

- Start with the core section; pick the others by role.
- Add a resource only if someone on the team has read it and can say why it helps.
- Note which chapters matter most; nobody needs to read everything.

## Core (all roles)

| Title | Author(s) | Why it helps |
|-------|-----------|--------------|
| The Pragmatic Programmer | David Thomas, Andrew Hunt | Daily habits of careful engineering. |
| Accelerate | Nicole Forsgren, Jez Humble, Gene Kim | Evidence on what makes delivery fast and stable. |
| Test-Driven Development: By Example | Kent Beck | The red, green, refactor cycle from first principles. |
