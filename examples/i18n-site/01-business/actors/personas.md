# Personas

## Purpose

Describe the people who use or are affected by the product, so that features, flows and
acceptance criteria are written for someone concrete. A persona is a working hypothesis built from
research; record where each one comes from and revise it when evidence changes.

## How to write a persona

1. Base it on interviews, support tickets, analytics or observation. Note the source.
2. Focus on goals, context and frustrations, not on demographic details.
3. Keep between two and five personas. More usually means the segment is not clear.
4. Give each persona a stable ID (`PER-NNN`) so specs and stories can cite it.
5. Use invented names and data. Never paste personal data of real users here.
