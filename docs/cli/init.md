# dixi init

## Purpose

`dixi init`: Create a documentary baseline in a new or empty destination.

Generated by `scripts/build-cli-reference.py` from the argument parser and the message catalog; do not edit by hand.

## Usage

```text
dixi init <directory> [--agent {none,claude,codex,skills}] [--profile {minimal,site,app,platform}] [--regulated] [--controls] [--existing]
```

The global options `--lang` and `--json` go before the command; see the [CLI reference](index.md).

## Arguments

- `directory` — Destination directory; its parent must exist.

## Options

- `--help`, `-h` — Show this help.
- `--agent {none,claude,codex,skills}` — Distributed integration: none (no agent), claude (Claude Code commands), codex (Codex skills) or skills (Agent Skills for other compatible agents).
- `--profile {minimal,site,app,platform}` — Content profile: minimal (default, current baseline), site, app or platform.
- `--regulated` — Add compliance, due diligence and stricter security templates (requires site, app or platform).
- `--controls` — Install opt-in agent hooks that enforce frozen tests, no secrets, no signing or merging, production-mode safety and verification before stopping (requires --agent claude or codex).
- `--existing` — Add DIXI to a folder that already has files: create only what is missing and never overwrite.
