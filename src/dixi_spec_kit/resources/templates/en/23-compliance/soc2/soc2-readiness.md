# SOC 2 readiness

> **Working aid, not legal advice.** This plan organises preparation for a SOC 2 examination. Only an independent auditor issues a SOC 2 report; no template certifies compliance or guarantees an opinion.

## Purpose

Decide whether a SOC 2 report is worth pursuing, which scope and criteria it would cover, and track the gaps between today and an audit-ready state with evidence for each control.

## Phases

1. **Scope**: answer the table above and write the [System description](system-description.md).
2. **Gap assessment**: fill the [Controls matrix](soc2-controls-matrix.md); every gap becomes a ticket and, when material, a risk.
3. **Remediation**: design and implement missing controls; keep evidence as it is produced.
4. **Readiness review**: walk through each control with its evidence; optional pre-assessment.
5. **Audit**: point-in-time (Type I) or observation period (Type II).
6. **Maintain**: controls keep operating; evidence is collected continuously.

## Evidence principles

- Prefer evidence generated by systems (logs, tickets, pipeline records) over screenshots.
- Each evidence item has an owner, a location and a collection frequency.
- Never back-date or reconstruct evidence; a missing period is a gap to disclose.
