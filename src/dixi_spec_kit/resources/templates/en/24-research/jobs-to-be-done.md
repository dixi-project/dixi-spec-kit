# Jobs to be done

## Purpose

Capture the jobs users are trying to get done, the circumstances that trigger them and the outcomes they value, so that the product is designed around progress users want to make rather than around features.

Status: draft. {{pending: confirm the main jobs with research evidence}}

## Job statement format

```text
When <situation>,
I want to <motivation>,
so I can <expected outcome>.
```

Write jobs without mentioning the product or any solution. A good job stays true even if technology changes.
