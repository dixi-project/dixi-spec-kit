# Support

## Purpose

Tell people where to ask questions, report problems and propose improvements for DIXI Spec Kit.

## Where to go

| Need | Channel |
|---|---|
| How to install or use `dixi` | [README](README.md) and the [support matrix](docs/support-matrix.md) |
| A bug in the CLI, a template or an agent command | Open an issue with the `dixi --version` output, your operating system, the exact command and what you expected |
| A new command, profile, template or integration | Open an issue first to agree on the scope, then follow [CONTRIBUTING.md](CONTRIBUTING.md) |
| A security vulnerability | Never in a public issue: follow [SECURITY.md](SECURITY.md) |
| Conduct concerns | Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

## What to expect

DIXI Spec Kit is maintained on a best-effort basis; there is no guaranteed response time outside security reports. Issues with a clear reproduction get attention first. The behavior of the AI model that runs the agent commands is outside the kit's control: report it to the provider of the agent you use.

## Before opening an issue

1. Update to the latest release and run `dixi doctor` in your project.
2. Run `dixi check` and include its output.
3. Search existing issues for the same problem.

## Resumen en español

Para dudas de uso, consulta el [README](README.md) y la [matriz de soporte](docs/support-matrix.md). Los errores y propuestas se abren como issue con la salida de `dixi --version`, el sistema operativo y el comando exacto; las propuestas grandes se acuerdan antes de escribir código. Las vulnerabilidades nunca van en una issue pública: sigue [SECURITY.md](SECURITY.md). Las conductas inapropiadas se reportan según el [código de conducta](CODE_OF_CONDUCT.md). El mantenimiento es de mejor esfuerzo.
